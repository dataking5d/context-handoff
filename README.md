# Context Handoff

> 把当前会话的关键上下文蒸馏成一份 markdown 交接文档，供新会话冷启动接手。
> Distills the current session's context into a markdown handoff doc for a new session.

## 这是什么

一个 Claude Code skill。触发后，它会把当前会话中**新会话无法自行获得**的信息
（项目定位、本次进展、已核实的结论、待办）整理成一份结构化 markdown，
写入 `~/.claude/handoffs/`，并给出可直接粘给新会话的接手指令。

为什么不用现成办法：

| 备选 | 问题 |
|------|------|
| 搬运会话 jsonl | 要改 `sessionId` 与 `cwd` 字段，跨机器几乎必错 |
| `SendMessage` | 仅传文本，Windows 下不可用，且不携带结论与待办 |
| 让新会话自己读代码 | 摸不进展过什么、为什么这么选、哪些已排除 |

## 快速开始

1. 把本 skill 目录放进你的 skills 目录：

   ```
   ~/.claude/skills/context-handoff/
   ```

2. 确认输出目录存在（不存在则创建）：

   ```bash
   mkdir -p ~/.claude/handoffs
   ```

3. 在会话中说「生成交接文档」或「handoff」即可触发。

**输出**：`~/.claude/handoffs/<YYYY-MM-DD>_<topic-slug>.md`

## 写什么（信息选择）

只交接「新会话无法从代码 / git / CLAUDE.md 自行获得」的信息：

- **项目定位**：这是什么、核心设计理念、关键路径与命令
- **本次做了什么**：按逻辑组织，不是流水账
- **已核实的关键事实**：可直接复用的事实，标注 `[已验证]` / `[推理]` / `[不确定]`
- **当前结论与决策**：达成什么结论、为什么这么选、权衡是什么
- **待办 / 后续**：下一步、遗留问题、清理项

**不写**：完整逐字 transcript、思考块、每条工具调用；不写能从代码 / CLAUDE.md /
`git log` 直接看出的东西。

## 输出模板

```markdown
# 上下文交接：<主题>

> 由 Claude Code 会话生成，交接给新会话继续。生成日期 <YYYY-MM-DD>。

## 一、项目 / 背景

<项目定位、核心设计理念、关键路径 / 命令>

## 二、本次会话做了什么

<按逻辑列出完成的工作>

## 三、已核实的关键事实

<可直接复用的事实，标注验证状态>

## 四、当前结论与决策

<结论、取舍、为什么>

## 五、待办 / 后续

<下一步、遗留、清理项>
```


## 已知限制

- **只输出一个固定目录**（`~/.claude/handoffs/`）。不提供"存到别处"的选项，
  这是为了让交接文档可被跨会话检索。
- **不传递运行时状态**。交接的是结论与待办，不是变量值、环境状态或进程句柄；
  这些新会话需要自己重新获取。
- **依赖模型自行判断"什么值得交接"**。信息选择这一步由模型完成，
  质量取决于模型对当前会话的理解，没有机械校验。
- **不解决跨机器环境差异**。新会话仍需自己确认依赖、凭据与路径是否就绪。
